# Standalone holo CLI

`tests/filesystem_lstat_public.test.mjs` is the explicit `test:native:fs-lstat` gate and part of `test:native`. Its Guest cases live in `conformance/capabilities/filesystem-lstat-native.test.mjs`; they verify the bounded withinRoot ordinary-file/directory subset and unchanged deny behavior. Final symlinks remain unsupported in withinRoot. Native Host-core owns exhaustive descriptor/ticket races; the public driver checks actual Guest results and untouched Host sentinels.

This Rust binary parses `holo [run] <entry> [argv]`, launches one private Runtime generation using the same executable, and maps its final exit status. It does not invoke Node, interpret JS APIs or implement module resolution.

`src/test_run.rs` owns explicit multi-file `holo test` admission: 1–256 preflighted files run sequentially in separate Runtime children, with one total deadline and CLI signal-handler lifetime. Reports remain per-file JSON lines; any failed child fails the batch. Test operands never silently become Guest argv. Ordinary run argv remains unchanged. Incomplete test execution cannot become success through early `process.exit(0)`; the V8 Host owns that terminal check.

`__plugin_validator_v1` is a private one-shot mode of that same executable: it accepts only bounded schema/config JSON, emits one result byte, and installs no Runtime or Host capability. The native adapter supervises deadlines, cancellation and cleanup; never expose arbitrary helper source, an executable override or schema inspection to Guest code.

`__observer_executor_v1` is a separate private, framed diagnostic helper mode of the same binary. It installs only a capability-free V8 isolate over exact prepared module plans, immutable JSON and callback-local publication, never the product Runtime/Node/Provider globals. Its actor/wire/deadline/owner-EOF and independent quota ownership live in `adapters/desktop/v8-host/src/observer_executor/`; Host profile resources and private output live in host-core. Do not reinterpret ordinary inline Cordis callbacks or expose this mode to Guest invocation dispatch.

`tests/observer_profiles_public.test.mjs` is the external Native CLI journey driver, run by `pnpm test:native:observer-profiles` and `test:native`. Public JS unit assertions remain in `conformance/capabilities/observer-profile-native.test.mjs`; the driver only configures Host fixtures, coordinates public-FS latches, checks private metadata/exit/cleanup and selects the real Rust executable. Node is a test driver, not the selected Runtime. Native Rust tests own exact wire, timeout, source-role and helper-failure matrices.

The private launch travels on stdin; EOF cancels an orphaned child. Guest argv starts after the entry, so strings resembling CLI flags there remain application arguments. `--timeout` bounds one execution, including synchronous loops and Promise microtasks.

`src/supervision.rs` owns CLI Unix signals and the private Runtime process group. Signal handlers only record atomics; the ordinary supervision loop closes the control pipe on SIGINT/SIGTERM/SIGHUP, allows one second for cleanup, then kills only its owned group. A second signal skips that grace. Launch writes are nonblocking so cancellation cannot stall behind a full pipe. Reaped child IDs are never signalled again. This is CLI cancellation, not Guest `process.on()` signal delivery. Real executable checks belong in `tests/signals.rs`.

Exit decisions use a final signal observation after collecting child status. A failed launch write allows up to 100 ms to collect an early child exit before reporting transport failure; its final signal observation gives already-recorded cancellation priority. Unit tests beside supervision cover these decision boundaries. Kernel waits remain bounded: forced reap allows 500 ms in the loop plus a 500 ms Drop fallback, rather than an unbounded `wait()`.

`--host-config` reads a bounded Host-owned JSON file and resolves installation paths relative to that file. `host-core/src/launch.rs` freezes the private schema; the V8 Host Context runs the existing shared Policy compiler before entry. Do not parse or derive SandboxPolicy authority in the Rust CLI.

`--process-profiles` reads a separate owner-only, nofollow Host manifest only when `--host-config` selects a logical `processProfileId`. The selected profile and its source identity travel in the private launch; Guest source admission rejects the manifest. A selected profile alone does not enable `host.process`: the compiled Policy/Provider intersection remains the startup authority.

An experimental v86 profile additionally requires `--process-backends` with a separate owner-only manifest. CLI checks the selected Backend ID and owner-controlled absolute artifact root, snapshots only the selected Host installation into private launch state, and labels the manifest private. Rust `native.v86.install` must still verify the artifact bytes and four profile digests before any Provider registration. Neither manifest is a Guest module or a public policy source.

The development-only `--experimental-v86-process` option requires both manifests and sets `experimentalEnable` only inside the private launch binding. Without it `host.process` remains startup-denied. The flag does not replace SandboxPolicy, Host capability admission or real public Process conformance.

`--watch` is run-only and requires `--host-config`. The private launch carries the absolute config path; the Host observes it, stages only plugin-array changes and keeps the Runtime alive. It is not source-file HMR, policy reload or entry restart. Tests belong in `tests/plugin_watch.rs` and use real JS invocations to establish old/new graph behavior.

Engine implementation belongs in `adapters/desktop/v8-host`, resource admission in `adapters/desktop/host-core`, and shared APIs in `packages/runtime`. Unit/integration coverage is in `tests/`; run `cargo test -p holonomy-cli`.

`tests/npm_corpus.rs` runs frozen published pure-JS packages through the real empty-PATH executable. Third-party bytes live under `tests/fixtures/npm-corpus/packages/`, with published `dist` names stored as `dist_asset` and restored only in each owned temporary fixture. Preserve their licenses and exact bytes; `package-assets.json` and its pinned manifest digest reject missing/changed/unlisted files before Guest execution. Do not format this vendor directory, depend on an ignored checked-in node_modules tree, or substitute a deep-import control for the intended bare-package case.

`tests/v86_network_public.test.mjs` is the explicit optional Native v86 network driver, run by `pnpm test:native:v86-network`. It requires the feature binary and pinned production assets, owns local Host fixtures and private configuration, and checks external effects. Public JS assertions live in `conformance/capabilities/process-network-native.test.mjs` and execute via real `holo test` with an empty PATH. Missing prerequisites fail this explicit gate; never count its outer Node test as the Guest test count or substitute a mocked VM.

`tests/v86_capability_public.test.mjs` drives the one-shot hoholo Device/System cases in `conformance/capabilities/process-capability-native.test.mjs`. `v86_public_fixture.mjs` owns pinned private configuration; `v86_public_child.mjs` owns actual-close tracking and bounded CLI/group cleanup. Child `error` cannot substitute for `close`; failed cleanup retains the fixture. Their pure fixture unit tests are part of `test:native:fixtures`, not VM acceptance. Network lifecycle Guest assertions live in the separate `process-network-native-lifecycle.test.mjs` and require real AbortError ordering, quota recovery and fresh-Runtime identity.

`tests/filesystem_names_public.test.mjs` runs the public filename interoperability cases from `conformance/capabilities/filesystem-names-native.test.mjs` with pre-existing raw Host names and external write/rename readback under both symlink profiles. `test:native:fs-names` is part of the ordinary Native gate. The optional `v86_filesystem_public` driver separately covers Linux tool access to those names and one-process file/directory quota reuse at `maxOpenHandles=1`; it requires the feature binary and pinned production assets. Diagnostic-only kernel/FD traces are not part of the shipped Runtime or a substitute for this public test.

`tests/filesystem_callbacks_public.test.mjs` runs Guest callback/Promise ordering and arity cases plus the Native fatal callback diagnostic. It is in `test:native:fs-callbacks` and the ordinary Native gate. `tests/computed_import.rs` covers live standalone source admission after entry, explicit root/Gate/privacy checks and CJS directory entry identity; managed immutable snapshots remain separate. Corpus executable overrides are test-only and require `HOLO_NPM_CORPUS_EXECUTABLE` plus its exact `HOLO_NPM_CORPUS_SHA256` pin.

`__source_snapshot_v1` is an owner-private source-only helper; it dispatches before V8 and shares the native SourceAdmission rather than granting Guest FS access. `RuntimeLaunch` version 2 accepts only an explicit private workspace root; Service derives that root from its stage, while standalone `--module-root` uses `src/source_root.rs` to canonicalize the Host selection and preflight every entry before dispatch. Without that flag standalone version 1 retains the entry-directory model. Keep actual main/argv and exact URL allowlist semantics when using nested entries; module-root selection is not a filesystem capability grant.

`tests/network_request_body.rs` exercises Host inspection using actual Guest Fetch with an empty PATH, including denied/late reads, ordinary oversized-for-inspection POST and Provider side-effect counts. Local HTTP test servers must explicitly make accepted sockets blocking before bounded reads: macOS can inherit O_NONBLOCK from a polling listener, and WouldBlock must not be interpreted as an HTTP EOF.

`tests/sustained_native_public.test.mjs` is the explicit `test:native:sustained` driver; public JS work lives in `conformance/capabilities/native-sustained-workload.mjs`. It requires a selected real binary, uses an empty child PATH, samples the CLI's unique direct Runtime child and verifies repeated FS/Crypto/HTTP work across plugin updates. The Host-only `HOLONOMY_NATIVE_SOAK_MS` accepts integers 185000–1800000 and defaults to 185000; it selects workload duration, not operation deadlines. `tests/sustained_native_fixture.mjs` owns HTTP upload-abort containment and actual Runtime-exit confirmation; its unit cases run in `test:native:fixtures`. Stream failures and post-completion close have bounded cleanup paths; uncertain fixtures are retained. Report observed duration and resource counts, not a leak ceiling or the entire Native acceptance plan.
