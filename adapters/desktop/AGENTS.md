# Native desktop Host

The bounded withinRoot `lstat` path admits ordinary files/directories through existing resolution tickets and pinned descriptors; final symlinks and namespace mutations stay fail-closed. `filesystem.rs` must not rewalk parent/name after consuming a resolved lstat descriptor. Native public coverage is `test:native:fs-lstat`; full ticket/identity race coverage stays in Host-core.

- `host-core/` owns engine-independent launch limits and descriptor-relative source snapshots.
- `host-core/src/launch.rs` owns the strict private launch/Host installation envelope; shared SandboxPolicy parsing remains in the JS Kernel.
- `host-core/src/diagnostic_audit.rs` owns explicitly selected bounded metadata-only source-read JSONL. `driver.rs` opens and labels it before any Guest source read; the Host-only native audit binding synchronizes admission before a source copy is returned. Audit retention/rotation remains Host-owned, and this does not install a Network body audit sink.
- `host-core/src/plugins.rs` owns Host plugin source roots, bounded package-directory link selection, nofollow leaf reads and device/inode handoff. Private root bindings retain requested package aliases and initial relative private names; public configuration cannot supply those compiled bindings. Absolute sources match only selected roots; the macOS `/var` spelling is normalized only after checking its root-owned system-link/parent trust conditions, not by following arbitrary source ancestors.
- `source.rs::PrivateSourceRoot` reuses the Host-role bounded walker for V2 canonical resources. Root/package FD leases and read budgets are shared and finite; multiple aliases of one canonical package do not consume separate package leases. A selected original package FD and its prior Schema/module snapshots seed the new root, preventing a path rebind from selecting replacement code. Source sidecars have a fixed adjacent source directory and exact read/alias/hash allowlists; cache hits must not bypass source roles or that allowlist.
- `host-core/src/source.rs` owns the shared Host/Guest source-domain admission. Known private namespaces are checked before Guest leaf open; pinned inode roles additionally protect aliases. Private launch bindings and plugin/watch reads reuse this owner. Keep the combined identity/slot/namespace budget bounded and labels conservative on candidate failure; scanning current inodes is not an atomicity proof. Explicit FS grants and publication of unregistered copies remain Host responsibilities, as described in the paired Host configuration guides.
- `host-core/src/source_snapshot.rs` owns the private source-only JSONL helper, dispatched by `holo __source_snapshot_v1` before V8 initialization. It shares SourceAdmission across private reads, Guest closure and later watch reads; never replace it with Node path checks. `readGuestResource` adds canonical URL identity; legacy `readGuest` stays nofollow. Trusted read purposes distinguish package metadata from source; weak Host metadata can serve the Guest planner without granting JSON execution, while strong private identities always win. Managed collection reserves its complete Service home before Guest reads. Private launch v2 adds the Service-owned workspace root; v3 adds bounded flat aliases; v4 adds physical package-metadata restrictions before any source cache read. Standalone v1 remains available.
- `openPrivatePackage` and `readPrivatePackage` retain a pinned Host package-root FD. A lease ID binds one immutable root identity/name; unchanged opens reuse it, while a renamed canonical root gets a new ID. Package resource accounting uses `(leaseId, relativePath)` size high-water marks rather than read counts, so config watch cannot exhaust it by rereading unchanged files. Missing private metadata paths still reserve names before returning null.
- `tools/runtime-plugin-config-validator.mjs` is the shared locked Ajv owner. `v8-host/src/plugin_schema/` supervises the private validator process; `plugin_schema.rs` owns bounded JSON admission and its capability-free V8 entry. Never enable Ajv codegen in live Host/Guest isolates. Watch uses cancellable background validation and publishes only after success; the helper's third embedded asset must remain covered by build/package digests.
- `host-core/src/plugin_watch.rs` observes bounded config snapshots and freezes every non-plugin field; `v8-host/src/plugin_watch.rs` owns one pending Cordis replacement and watch liveness. It never edits Policy or restarts Guest entry.
- `host-core/src/filesystem/` owns native descriptor-relative filesystem I/O and handles. Every call checks the compiled root rights plus selected Provider constraints before I/O.
- `filesystem/metadata.rs` owns typed timestamp/access/truncate/sync OS effects and exact Host-only stat snapshots. `resources.rs` retains directory FDs as well as files in one quota/close ledger; directory snapshots come from the retained FD, not a later pathname reopen. `bootstrap/providers.mjs` strips virtual fd selectors only after Kernel binding resolution and rolls back native bindings if snapshot/publication fails.
- `filesystem/resolution.rs` owns bounded withinRoot resolution tickets and exact pinned execution descriptors. Providers must consume those descriptors rather than rewalk names after admission. Conditional namespace mutations without safe platform primitives remain fail-closed; directory-object capabilities retain their identity after a later rename.
- Canonical FS resource segments and selected prefix constraints remain URI-encoded on the private JSON wire. `filesystem::segments()` validates and decodes exactly once into native names before OS access and prefix comparison. Resolution results, symlink targets and directory entries are raw native names; bootstrap encodes resolution results once when rebuilding canonical URLs. Never decode raw names or change shared resource identity to repair Host filename interoperability.
- `filesystem/rename.rs` owns two-target identity tickets; `filesystem/watch/` owns kqueue subscriptions, non-reused node tokens and bounded child snapshots. Watch events cross the shared Resource Registry; native errors must first become a complete shared Node error snapshot.
- `v8-host/` owns the `rusty_v8` isolate, module evaluation, microtask checkpoints and Host callbacks.
- `v8-host/src/callback_diagnostic.rs` owns bounded fatal callback, entry and rejection extraction. It rejects Proxy/unsafe values before native own-data inspection and never reads Guest stack/coercion hooks. Locations resolve native frame Script IDs through the bounded per-isolate registry populated at actual module/CommonJS compilation; frame names and Message resource names are sourceURL-spoofable and cannot prove origin. Unknown/overflow locations are omitted. `driver.rs` owns the Promise/nextTick rejection boundary before ordinary work and the configured-Host cleanup fence.
- `packages/runtime/src/module-loader/commonjs-runtime.ts` owns CommonJS callable/metadata rules; `v8-host/src/commonjs.rs` binds them to engine evaluation and already-admitted graph lookups. Resolve-only edges cannot become executable alias loads. Never coerce a Guest object to a require specifier or resolve against mutable module metadata.
- `src/inspector.rs` owns the Guest-only V8 Inspector and private Unix session. Executable commands use the existing Policy/Gate owner; client sourceURL never becomes authoritative origin. `bootstrap/inspector-methods.mjs` is the exact Native method/Policy mapping, not a public permissive fallback.
- `inspectorWaitForDebugger` is a private launch bit, valid only with the private socket. The original Guest-thread pump holds entry after Host/plan admission; early resume never enables execution before `begin_entry`. Service leases adapt this single connection rather than registering another engine Context or Gate.
- `src/module_planner.rs` and `bootstrap/module-planner.mjs` own the private planning Context using the shared HolonomyModuleLoader. Never serialize plans in Guest realm or expose planner objects/errors/functions. Native HDO identity binds ESM/CJS importer provenance; `control/module_gate.rs` polls existing Gate tickets without blocking Guest, and `ImportLease` counts admissions even while the queue is drained. The planner is a digest-checked embedded asset, not a second resolver.
- `v8-host/src/control/` owns a native Host worker with its own V8 isolate; `bootstrap/control.mjs` remains the unique shared admission/Broker/plugin controller. Host handles stay in worker state; Guest callbacks/resolvers stay in `RemoteControl`. Only bounded owned messages cross threads. Read [Host execution](.oo/rules/host-control.md) before changing transport, liveness, deadlines or shutdown; controlled strings are Policy-first; Wasm and other ingress remain separate.
- `bootstrap/plugins.mjs` owns initial Cordis installation and teardown; `bootstrap/engine-gate.mjs` owns per-generation shared Gate metadata/decision validation. Native callback hooks belong in `src/engine_gate.rs`; they preserve original V8 lexical semantics and never parse a second Policy. `src/wasm.rs` owns no-callback BufferSource staging for non-streaming Wasm; `bootstrap/wasm.mjs` brackets the captured engine APIs, including Promise rejection delivery. Shared Gate dispatch/registry own decision-versus-settlement leases; Native monitor owns deadline/cancel acknowledgement.
- `src/plugin_graph.rs` admits whole versioned plugin plans before mutating caches. Dynamic-import ownership is carried by private V8 host-defined-options identity, never sourceURL text; pending imports retain their original Context and graph until terminal delivery. Retired graphs are released only after Cordis revision drain/dispose.
- `host-core/src/network/` owns pinned HTTP/TLS transport; `bootstrap/network-provider.mjs` binds it to shared admission. `bootstrap/native-port-{host,guest}.mjs` is the single owned-message NativeBridge route for Network and Storage; Storage requests re-enter the existing Kernel/Broker before the Provider can start Rust I/O. Host authority and resource identity stay out of Guest data.
- `host-core/src/process_network.rs` and `v8-host/src/process_network_io.rs` own separate hidden Process DNS/socket/HTTP transport; never reuse ordinary Fetch Policy as a Process grant. Prepared DNS tokens bind only in the shared Process preflight's final resolved context and are consumed after the Kernel receipt returns. Physical blocking DNS reservations survive cancellation until the OS returns. `bootstrap/process-v86-network-{port,broker}.mjs` owns receipt pairing, bounded Host write queues, per-flow cleanup and VM event routing; it does not install another Provider or Guest API.
- `host-core/src/storage.rs` owns the optional persistent KV/SQLite worker, namespace/family identity and disk/SQL bounds; `v8-host/src/storage_io.rs` owns its asynchronous Host promises. `bootstrap/storage-provider.mjs` binds selected Policy/Cordis authority to Rust. Read the paired Storage guides before extending it: credentials and a same-owner descriptor-pinned SQLite VFS are not implemented. Read-only operations never create database files.
- `host-core/src/device.rs` owns selected Device Policy rechecks and operation-local source revision; `device/darwin.rs` owns bounded CoreGraphics/IOKit metadata probes and native object release. `bootstrap/device-provider.mjs` owns authority meets and sampled subscriptions, using the existing Host referenced timer only while Device resources live. `resource-subscriptions.mjs` retains typed Device overflow/revision maps without FS/Process error tuples. No generic resource callback keepalive change is permitted; preserve FSWatcher persistent:false. Read paired Device guides for the physical-change evidence boundary.
- `bootstrap/native-observer-platform.mjs` owns the exact partial Native Observer descriptor and Host caps, with no I/O or bootstrap dependency; Native and Service reuse this single metadata leaf. `bootstrap/native-observer.mjs` binds the shared Observer registry and re-exports that descriptor. `src/observer.rs` emits real, source-free engine metadata through a dedicated bounded channel; this never substitutes for Gate authorization. Callbacks remain in the trusted Host worker: synchronous callbacks can block indefinitely without an explicit Runtime deadline, cancellation or another fatal watchdog condition. Standalone timeout defaults to none; Observer async timeout is not preemption. Host timers retain referenced/unreferenced metadata in `control/state.rs`. Inline plugins do not gain a general Host log/export route; isolated diagnostic profiles below explicitly select their own bounded metadata sink. A V8 console object alone establishes neither route. See the paired Observer guides.
- `host-core/src/observer_profiles.rs` owns separately selected diagnostic module resources and private compiled profile bindings; `observer_sink/` owns strict source-free JSONL schema/history and its bounded asynchronous writer. `secure_metadata_file.rs` is the shared FD/identity/permission/lock primitive also used by source-read Audit; never duplicate its path checks.
- `src/observer_executor/` owns the same-binary capability-free diagnostic helper, exact module-plan instantiation, typed outcomes, callback tokens, deadlines, restart epochs and owner-EOF cleanup. Shared helper ownership/RSS/reaping comes from the existing schema transport with independent Schema/Observer quota pools. `bootstrap/observer-profiles.mjs` plans private sources and installs only nonblocking forwarding stubs in the Main Host; profile user code must never execute there. The hidden CLI mode is not a general Runtime/Provider or Guest API. See paired isolated-profile guides and the source preflight ordering in Host execution rules.
- `host-core/src/v86.rs` owns bounded private VM asset, serial and network command lifecycles. Under Cargo feature `v86-backend`, `v8-host/src/v86_vm.rs` runs pinned v86 JS/Wasm in a dedicated VM isolate thread. `bootstrap/process-v86-backend.mjs` composes the shared Process/FS/Network bridges; family-specific codecs live in `backends/v86/host/`. The experimental profile admits one `/workspace` mount and only explicitly restricted Process networking, with actual seccomp source support; descendants remain denied. Default `holo` does not embed v86 or enable Process. The opt-in `v86_process` tests cover process/stdio/FUSE; `test:native:v86-network` drives six real Guest JS cases from `conformance/capabilities/process-network-native.test.mjs` and checks external effects, never substituting Node/Host assertions for Guest results.
- Native response streams retain connection slots until terminal/close and advance only on credits. `network-response-body.mjs` owns Host-only iterator cleanup; shared Fetch owns clone/tee. A native Job cancellation flag fences queued head/pull completions before stream insertion. `host-core/src/network/tests.rs` covers native queue/cancel/quota races directly; do not treat unrelated Host unit counts as streaming evidence.
- The optional VM network uses pinned `assets/v86-network.js` hooks and a build-only `generated/v86-web-standards.js` leaf. Build both with `tools/build-native-runtime.mjs` before Cargo; default Native does not embed the VM leaf. Keep serial attribution ahead of packet delivery, enforce VM flow/terminal reservations and Host TCP/UDP Promise-tail byte limits, and verify every DNS address with the shared classifier. Local I/O tests and fake VM tests are not real Linux traffic acceptance; keep descriptor/support promotion separate.
- `v8-host/src/v86_vm.rs` keeps every owned VM isolate exited between calls; private RAII entry/exit and Context reset before disposal allow interleaved/non-LIFO environment teardown. Pinned rusty_v8 enters on construction and expects an entered isolate at Drop; recheck this contract on engine upgrades. `process-v86-backend.mjs` binds selected Device/System domains to the single `backends/v86/host/capability.mjs` owner. Real hoholo tests use the existing Native Device Provider/System projection, not a second facade or ambient OS read.
- `host-core/src/crypto*` owns synchronous ring primitives, OS entropy and bounded native context storage. `v8-host/src/crypto.rs` performs no-callback binary copies; `bootstrap/crypto-provider.mjs` only binds the shared CryptoPrimitivePort. Crypto does not use NativePort/Broker or reimplement Node/Web facades. Shared installation self-tests exercise native primitives before entry; raw key/AAD/plaintext copies are best-effort zeroized, not a guarantee about opaque ring state or fatal OOM.
- `host-core/src/darwin_process.rs` owns the private `__process_io_v1` same-binary helper before V8 initialization: installed executable ID resolution, static Seatbelt containment, bounded stdio/event queues and owner-EOF job cleanup. `bootstrap/process-darwin-*` binds that port to the existing shared Process Provider/ledger; `process-backend-registry.mjs` is Backend-neutral. Do not expose native PIDs/paths or add a second child_process facade. The current profile denies fork/re-exec, mounts and network; ceilings do not open unsupported authority.
- `bootstrap/resource-subscriptions.mjs` owns the single bounded Host event relay and disposal for FS and Process resources. It gets event schema/provider identity from the Kernel's trusted publication, polls every installed Provider with `poll()`, and reserves terminal capacity before ordinary events fill the queue. Normal and synthetic close both release Host subscriptions; the Process Guest facade unsubscribes its Rust-held callbacks on child and stream close. Guest resource behavior remains in the matching Capability package. `conformance/capabilities/process-native-darwin.test.mjs` owns profile-bound public JS assertions; the Service's native-darwin-process-public tests exercise the real standalone and managed targets. Binary safe snapshots stay in the shared Guest support and existing SHA owner, not this adapter.
- `v8-host/bootstrap/` composes existing `packages/runtime` leaves; never implement a second JS facade or scheduler here.
- `bootstrap/main.mjs` prepares module export descriptors before planning, then `initializeCapabilities()` installs the shared Process property snapshots only after Host Kernel/plugin admission and before Guest module evaluation. Replacement bindings must retain the planned export names; denied fields never gain ambient Host fallback values.
- `tools/native-cli/` owns the standalone `holo` executable and its private child-process launch control. Private `moduleAllowlist` restricts Service snapshots before any source cache hit; ordinary standalone query identities remain available without that option.
- Isolated handoffs must diff against their captured initial source baseline. Do not compute a before-hash from later live main state and accidentally revert concurrent edits; an apply-clean patch is not proof of ownership correctness.
- `tools/native-release/` owns local development archives, build-input/asset digests and relocated Node-free execution verification. It does not claim signed or redistributable release status.
- `tools/build-native-runtime.mjs` compiles the trusted Runtime into an embedded JS asset. Node/esbuild is a build dependency only; the shipped executable must run with no Node executable or JS package directory.

Module reads use opened directory descriptors and retain immutable bytes per generation. Source resource reads may follow bounded relative package-directory links under node_modules inside the pinned root, never arbitrary file links or private source aliases. Canonical resources share their byte cache; the shared Module Loader still owns package resolution and module identity. No Host global or bootstrap controller survives into user code. Native Providers must enter the existing Broker before being published.

Verify with `node tools/build-native-runtime.mjs`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings` and shared JS regressions when touching package contracts. Binary tests belong beside the CLI; public behavior assertions remain in JS conformance.

Host-side JS Provider boundary tests live in `v8-host/tests/`, run by `pnpm test:adapter:desktop:unit`. This entry generates its embedded JS assets first and must also work without a pre-existing `v8-host/generated/` directory. They may inspect native transport bindings; platform-neutral `__tests__/js-api` suites may not import Desktop Providers. `pnpm test:native` also runs this layer and native packaging tests after the executable tests.
