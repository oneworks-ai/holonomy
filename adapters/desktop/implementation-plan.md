Do not mark this objective complete from the core execution tests alone. Node Adapter and Android evidence only establish reuse candidates. Each native Provider and diagnostics surface needs native executable evidence before support is published. AgentOS/WASIX and other previously deferred Backend work remain deferred.

The Native Darwin Process subset reuses the shared facade, Broker, resource ledger and callbacks. Its private Rust I/O helper is the same binary, with no Node/libnode dependency. Static Seatbelt currently requires network:none, mounts:[], zero writable-rootfs budget and processTree scope, denying fork/re-exec. Public JS tests cover sync/callback/shell, binary streams, timeout/output cap/Abort/signals; real Service tests cover immutable profile staging, plugin watch and stop, with a separate forced-Runtime-SIGKILL cleanup case. It is not descendant syscall mediation or arbitrary macOS shell/FS/network support. The shared 1 MiB invocation envelope remains in force even where aggregate stdio quotas are larger.

## Native acceptance queue

- The frozen npm corpus has 18 standalone cases, including YAML document promotion and Acorn API-index applications with independent Host output/digest checks and failure-without-output paths. This extends real-package evidence without declaring complete npm compatibility or adding a second Loader.
- `test:native:sustained` selects a real empty-PATH executable and 185000–1800000 ms of repeated FS/Crypto/HTTP work across plugin revisions. A 300000 ms run completed 290 rounds and actual CLI/Runtime exit. Bounded HTTP-abort containment and Runtime-absence checks belong to its Host fixture; observed FD growth includes retained config identities and is not a leak ceiling.
- Native in-flight recovery independently checks transport admission, socket and child close, single-connection quota reuse, and fresh-generation completion after restart, stop/restart and unexpected Runtime exit. Active response bodies aborted after headers preserve Guest-local signal reasons; default `AbortError` is an Error, not complete DOMException compatibility. Before-header/pre-aborted requests and transport-EOS buffered clones retain the narrower documented boundary. These checks do not inject a late Host terminal across generations; that owner-level matrix remains a separate acceptance item.

- Native macOS arm64 now explicitly installs the six-required Desktop Device vertical chain: summary, form-factor, display, input, lifecycle and events.subscribe with display/lifecycle events. Real OS reads, initial snapshots, queue overflow/getter resync, permissions and restart/close have Native executable evidence; physical display/lifecycle changes were not induced or independently observed, so full physical-change acceptance remains open. Other optional operations remain unsupported, not ambient fallback or a substituted Headless Node descriptor.
- Managed Native Wasm/dynamic-import uses the same existing Host plugin Gate as direct execution; static plugin startup also works for `holonomy test --config`, with watch still run-only. An explicit owner-only Native source-reader installation is selected independently for each boundedSource run, never from Node callback authority. Inline Native Observer subscriptions belong to initial/watch Host plugins using the single Native descriptor; Service Node callback IDs remain unsupported. Service separately installs immutable Native diagnostic module profiles with request/version pins and per-generation private sinks; the owner can separately install synchronized Native source-read audit with Service-derived generation paths, reusing the Rust writer rather than inheriting Node/Android evidence.
- Standalone Native diagnostic profiles now explicitly select private module resources, capability-free same-binary helper processes, shared-registry forwarding stubs and bounded owner-only JSONL output. Helper loops/pending/rejection/fatal VM failures are independently contained; no arbitrary inline closure is moved and the authorization Host is not recovered with CancelTerminateExecution. Sources/configs, queues, initialization/callback deadlines, heap/RSS monitoring, restart epochs and owner EOF have focused executable tests. Old inline observe remains partial. Service profile registry/admission/staging now reuse this executor, with Policy/version revalidation and private generation resources. Broader long-run/target acceptance remains open; profile startup preflight finishes private dependency classification before Guest source planning.
- Bounded pure-JS ESM Host dependency closures use the shared immutable graph contract and trusted Native resource preparation. Host/Guest package-scope metadata can be shared for planning without authorizing Guest JSON execution; cache aliases, direct imports and later regrants keep their source admission. Broader real-package/cross-root-store acceptance remains separate; do not introduce ambient Node imports or rewrite Guest authority to make a corpus green.
- Archive validation includes relocated empty-PATH Wasm execution and module allow-deny, not just engine metadata. It remains scoped execution evidence; complete Native acceptance and production distribution gates are separate.
- Managed stop publication preserves a same-generation natural exit through one registry transaction, including failure compensation; finalizer errors select a failed operation rather than leaving it running. Unconfirmed OS cleanup retains cleanupPending. Bounded write retries do not claim durable completion when the state store is permanently unavailable.

- Standalone `--module-root` reuses private launch v2 and the existing SourceStore: explicit canonical containment is checked for every test before the first entry runs. The default remains entry-directory bounded; source admission does not grant FS access or change Guest cwd.
- The frozen real npm corpus includes a Cordis/YAML plugin lifecycle application and Ajv validation with explicit Engine Gate allowance and default-denied code generation. It covers 14 pinned package closures; it does not establish complete npm compatibility or cross-root-store support.
- Real Linux curl HTTPS uses opaque TCP authority and a public CA mounted readonly through FUSE; curl, not the Host Broker, verifies the certificate/hostname. Wrong CA/hostname, Policy/middleware denial and redirect authority have real Guest cases; this is not Host HTTP inspection of encrypted bytes or generic CONNECT support.
- Linux filesystem tools have real Guest coverage for cat, mkdir, cp, mv, rm, touch, ls, positioned writes preserving suffixes, append, file/directory sync, Host refusal and readonly mounts. Descriptor-pinned opaque directory resources share the existing Kernel quota/publication/close lifecycle and survive pathname replacement without syncing a new inode. Explicit fresh chmod authority now supports standard path/fd/FileHandle forms, real mode readback and pinned-FD expected-kind checks. Native Git init and empty status pass with Host HEAD/config/objects readback; this is not clone/push/hooks or whole-Git acceptance. Native mode-000 path pinning remains conservatively partial; retained FDs restore mode000. Default Guest Stats retain Node's non-bigint shape, while precise Ns stays Host-only.

Build tools may use Node, but runtime execution, native control and Providers must not spawn Node or link libnode. JavaScript API/scheduler/test semantics remain in `packages/runtime`; Rust owns V8 and OS primitives. Rust additions never replace the existing M4 Node/Android changes in the shared worktree.
