# Runtime package

`@holonomyjs/runtime` is the platform-neutral Runtime and Cordis composition package.

- `src/app/` owns Runtime creation, Cordis App/plugin graph, lifecycle and the reviewed default module composition.
- `src/app/plugin-bundle.ts` retains the exact self-contained V1 contract. `plugin-bundle-v2.ts` owns canonical byte/metadata/alias snapshots and mixed-version validation; it does not resolve packages or install platform support. Source closure resolution stays in the shared Module Loader. Use portable encoding primitives here, not ambient Node I/O or size-sensitive backtracking regular expressions.
- Composed `process.nextTick` uses that Runtime's caller-owned Event Loop, tracks its own queued task IDs and fences disposal without shutting down another Runtime's loop. The capability process override accepts only a local `processControl.nextTick` delegate; it must not send callbacks through the Broker. `runNextTickCheckpoint` runs only the existing tick phase and retains normal budget/termination rules; adapters own engine checkpoint placement.
- `src/timers/runtime-immediate.ts` owns composed Immediate handles/callbacks; `src/event-loop/` owns their FIFO check batches, reference liveness and cancellation. The raw timer factory remains timeout/interval-only. Host wakeup phase distinguishes urgent ticks from ordinary work so adapters can yield to I/O without creating a second scheduler. Error classification uses captured private WeakSet brands, never `instanceof` on arbitrary Guest-thrown values.
- `src/kernel/` owns shared Policy, Broker, invocation snapshots, authority, canonical-resource bases, resource registry, error delivery and machine contracts.
- `src/native-port/`, `src/event-loop/`, `src/module-loader/`, `src/node-compat/`, `src/streams/` and the other leaf directories own system-independent JavaScript runtime primitives.
- Capability-specific facades and registries belong in `packages/capabilities/*`; platform Providers and engines belong in `adapters/*`; environment implementations belong in `backends/*`.
- `src/module-loader/` is the single owner of package imports/exports, nearest-package scope and fixed condition profiles. Selected package targets are exact; legacy file/main probing is separate. Synthetic membership requires an own registry key, including bare built-in aliases. New resolver work must retain verified-read budgets, transaction rollback and no Host reentry.
- `HolonomyModuleLoader.createSourceClosure` returns a distinct non-executable source snapshot with exact positive bytes/package metadata and opaque external references. It uses a private loader, not fabricated bindings or the executable plan cache; actual runtime linking still validates builtin availability/exports. New cache-discriminant checks must use own properties, not inherited `kind` tags.
- Ordinary executable plans defer all dynamic imports, including literals, to runtime planning so Guest rejection is catchable. `captureDynamicImports` is an immutable constructor mode for trusted Host executable graphs, never a per-plan cache switch. Source-closure loaders capture literals in private state. Native plugin/Observer graph builders explicitly select capture mode; the Guest planner stays lazy. Preserve those separate cache and source-role owners.
- `HostModuleSource.canonicalUrl` is an optional trusted read fact, not a second resolver. The loader validates root/query/fragment identity and both integrity keys, then keys package roots and executable caches by canonical URL. Source closures emit canonical reads and a separate flat aliases list; transaction rollback includes alias cache entries.
- Trusted read contexts distinguish `module` and `packageMetadata`; `metadataOnly:true` is a Host restriction, never Guest input or an executable grant. Source/alias/module/resolution caches must recheck module admission before turning metadata into code, including exports/imports targets. Regrants compare retained exact bytes, digest and canonical identity; rollback restores prior permissions. Source closures preserve restrictions without changing the Host V1/V2 bundle format.
- `src/node-test/assert-error-matcher.ts` owns the common throws/rejects validation; `assert-deep-value.ts` owns content comparison using captured internal-slot probes, including foreign-realm values. `testPromiseBrand` is an optional trusted synchronous engine predicate passed through the existing composer; Node/Native install it. It is not an I/O capability. The direct portable assertion factory's fallback uses a captured native Promise-then probe, so complete Promise-species observability parity is not claimed there.
- The package may compose official Capability entrypoints, but Kernel leaves must not import platform Provider implementations or own Host I/O.

Build output is generated in `dist/` by the root `pnpm build`. Do not edit `dist/` or the checked-in machine JSON directly.

Verify changes with `pnpm typecheck`, `pnpm test:runtime`, `pnpm contracts:check`, `pnpm lint` and `pnpm format:check`.
